# UI flow

Component-by-component behavior notes. Read the section for whatever screen/component you're touching rather than all of it.

- `OnboardingPage` (`src/pages/`) — first-launch-only chain picker (multi-select chips over `chains.json`), calls `completeOnboarding(chainIds)` and routes to `/`. `ProfilePage` has the same picker (`togglePreferredChain`) for changing it later.
- `SwipeDeck`/`SwipeCard` (`src/components/`) render a draggable card stack via Framer Motion. Swipe right → `like()` + shows `AddedToCartOverlay`, left → `pass()`, up → navigate to `/recipe/:id` without deciding. `SwipeCard` uses two separate motion values for its `y` axis — `dragY` (inner layer, bound to the drag gesture) and the outer wrapper's `animate={{ y: stackIndex * 12 }}` (stack offset) — don't collapse these back into one `y` value, Framer Motion can't cleanly animate the same motion value from both a gesture and an `animate` prop at once.
- `AddedToCartOverlay` (`src/components/`) — the celebration shown right after a right-swipe: a seeded confetti burst (deterministic per `recipe.id`, so it doesn't re-randomize on re-render), calories per serving, the meal-count stepper (`mealCounts[recipe.id]`, via `setMealCount`), and a live cheapest-chain price preview that reprices as the count changes. The primary button ("✓ Sepete Eklendi, Devam Et") is the confirm-and-continue action; "Fiyatları Karşılaştır" routes to `/recipe/:id` instead.
- `RecipeDetailPage` (`src/pages/`) is shared by two flows: reached via swipe-up (preview, not yet in cart) and via `CartPage` or `AddedToCartOverlay` (already in cart). It checks `decisions[id]?.liked` (as `isInCart`) — if not, it shows a locked teaser with inline like/pass buttons instead of the price table; once in cart, it shows the same meal-count stepper as the overlay (kept in sync via the shared `mealCounts` store field), then the `computeBasketTotals` breakdown filtered to `preferredChainIds` and scaled by the chosen meal count. **The cheapest chain is shown once** — as the "En Uygun Market" summary card — and excluded from the ranked list below it (`totals.slice(1)`, under an "Diğer Marketler" heading) to avoid the duplicate-listing bug that existed earlier. Ingredient lines link to real calorie data for any ingredient present in `product_catalog.json`.
- `CartPage` (`src/pages/`) lists cart recipes (`CartRow`: photo, per-serving-count calories, meal-count stepper, an expand/collapse toggle revealing the recipe's ingredient list, and a per-row remove button). Header has a "Sepeti Boşalt" button gated behind `ConfirmDialog`. A `sticky bottom-3` button (this works because `CartPage`'s `PageFade` root sits inside `App.jsx`'s `overflow-y-auto` scroll container, whose box height already stops exactly above `BottomNav` — sticky positioning resolves against that scrolling ancestor, so `bottom-3` lands the button just above the nav bar with no manual offset math needed) opens `ShoppingListModal`.
- `ShoppingListModal` (`src/components/`) — two-step popup: step 1 lets you check/uncheck which cart recipes to include and adjust each one's meal count (shared `mealCounts` again); step 2 (reached via the "🛒 Alışveriş Listesini Oluştur" confirm button) shows the combined list from `buildShoppingList` with a "Listeyi Kopyala" button (`navigator.clipboard.writeText`, brief "Kopyalandı ✓" feedback).
- `ProfilePage` (`src/pages/`) — `LoginPanel` (Apple/Google/Email buttons) when logged out, a profile card when logged in: tappable avatar (real photo from `profile.avatar_url` if set, initials fallback otherwise; a 📷 badge opens a file picker that resizes via `src/lib/resizeImage.js` — the same helper `CreatePostModal` uses — uploads to the `avatars` storage bucket, then updates `profiles.avatar_url` and calls `useAuth`'s `refreshProfile()` so the new photo shows immediately), name/email/provider, real follower/following counts via `useFollowStats`, sign-out. Then a compact `PremiumPaywall`; a "Paylaşımlarım" grid of the user's own posts (`useUserPosts`, links to `/post/:id`); a "Kaydedilenler" saved-posts thumbnail grid (`useSavedPosts`, same link pattern); and the existing preference sections (chains, dietary filter, city, deck reset).
- `SocialPage` (`src/pages/`) — an Instagram-style feed of real Supabase `posts`, via `useCommunityFeed`, rendered through the shared `PostCard` (`src/components/`). Filter section above the feed, three independent layers combined client-side (no extra queries): an audience row ("Tümü" / "Takip Ettiklerim", filtered against `useFollowingIds`' follow-target set), a sort toggle ("En Yeni" / "En Popüler", the latter sorting by like count), and a horizontally-scrolling category chip row over `posts.tags` (same vocabulary as recipes — `src/lib/tags.js`'s `ALL_TAGS`/`tagLabel`; single-select, "Tüm Kategoriler" clears it). Logged-in users get a "+ Tarif Paylaş" button opening `CreatePostModal` (photo upload → resized client-side via `src/lib/resizeImage.js` to a JPEG `File`, uploaded to the `post-photos` storage bucket; title; description; an **optional** tag multi-select over `ALL_TAGS`; and a **required** multi-select of every ingredient used, grouped by category) — logged-out users see a "Paylaşmak için giriş yap" link to `/profile` instead.
- `PostCard` (`src/components/`) — shared between `SocialPage`'s feed and `PostDetailPage`. Action row: like (❤️/🤍 + count, `post_likes`; double-tap the photo also likes, Instagram-style, never unlikes), comment (💬 + `commentCount`, opens `CommentsModal`), share (Web Share API with a `navigator.clipboard.writeText` + "Bağlantı kopyalandı ✓" fallback, linking to `/post/:id`), save (an inline bookmark-ribbon SVG — outline when not saved, filled `currentColor` when saved — matching Instagram's save icon rather than an emoji; backed by `post_saves`, private, see docs/SUPABASE.md), and on another user's post a "Takip Et" follow button (`useIsFollowing`/`follows` table). Official posts (`post.isOfficial`, `author_id === null` — see docs/SUPABASE.md "Official recipe posts") show "Tarifim Mutfağı" with a ✓ badge instead of a follow button, plus a "Tarifi Gör →" link to `/recipe/:id` when `recipeId` is set. Delete button shows for the post's own author (`ownedByMe`) or for an `is_owner` account (moderation, see docs/SUPABASE.md) — never for both a follow button and delete on the same post.
- `PostDetailPage` (`src/pages/`, route `/post/:id`) — the deep-link target for PostCard's share button (works because this app uses `HashRouter`, so shared links look like `.../#/post/<id>`). Finds the post inside `useCommunityFeed`'s already-fetched array rather than a dedicated single-post query — fine at this app's scale.
- `CommentsModal` (`src/components/`) — bottom-sheet, same visual pattern as `ShoppingListModal`/`CreatePostModal`. Backed by `usePostComments(postId)`; only renders the reply input when a user is logged in; comment authors can delete their own.
- `CoachPage` (`src/pages/`, route `/coach`, 5th `BottomNav` tab "Koç") — see docs/PREMIUM.md.
- `RecipeArt` renders the recipe's real photo (`recipe.image_url`, all 101 recipes have one) or, if absent, a deterministic gradient + emoji block hashed from `recipe.id`. Also used at small sizes for cart rows and shopping-list checkboxes.
- `PageFade` (`src/components/`) — every page's root is wrapped in this (`initial={opacity:0,y:10} → animate={opacity:1,y:0}`), so navigating between screens has a quick, consistent entrance instead of a hard cut.
- `ConfirmDialog` (`src/components/`) — generic "are you sure" bottom-sheet/modal (title, description, confirm/cancel). Used by `CartPage`'s "Sepeti Boşalt"; reach for it before adding another one-off confirm UI.
