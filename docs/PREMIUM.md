# Premium & AI health coach

A `subscriptions` table (`supabase/schema.sql`) holds one row per user: `plan` (`free`/`premium`), `status`, `store` (`app_store`/`play_store`/`stripe`/`manual`), `current_period_end`. It has **no client-facing insert/update RLS policy at all** — this is deliberate, not an oversight. A user must never be able to grant themselves premium by calling the Supabase API directly. Real writes are meant to come from a trusted server context once a payment processor is wired up (for the planned iOS release: Apple's App Store Server Notifications, or a RevenueCat webhook, hitting a Supabase Edge Function that authenticates with the `service_role` key). **Stripe is deliberately not used for the in-app purchase itself** — Apple requires StoreKit for subscriptions unlocking content inside an App Store app, and using a third-party processor there risks rejection; Stripe/web billing could still make sense for a companion website, but that's out of scope here. Until StoreKit is wired up (needs a Mac + Xcode + an Apple Developer account, none of which exist in this dev environment), the only way to test premium locally is a manual insert via the SQL Editor — template at the bottom of the `subscriptions` section in `schema.sql`.

`useSubscription(userId)` (`src/hooks/useSubscription.js`) is the read-only client view of this — `isPremium` also checks `current_period_end` hasn't passed. `PremiumPaywall` (`src/components/`) is the single reusable paywall UI: an "active" state (badge + expiry) when premium, and an honest "not yet purchasable, coming with the iOS release" state otherwise — **it deliberately has no "Buy" button that writes to the database**; that would defeat the whole point of the RLS design above.

The flagship premium feature is `CoachPage` (`/coach`, 5th `BottomNav` tab) — a chat UI (`useAiCoach`) against `supabase/functions/ai-coach/index.ts`, a Supabase Edge Function (Deno). The function re-verifies premium status itself against `subscriptions` using the `service_role` key before calling Claude (`claude-opus-5`) — it does **not** trust a client-supplied "I'm premium" claim, since a client could call the function directly and skip the UI gate entirely. `ANTHROPIC_API_KEY` lives only as a function secret (`supabase secrets set ANTHROPIC_API_KEY=...`), never in `VITE_*`/client code, for the same reason the Supabase `service_role` key must never be. Deploy with `supabase functions deploy ai-coach`. The chat is stateless per the underlying Claude API — `useAiCoach` resends the full message history each turn — and is given light context (`dietaryFilter`, cart recipe names via `cartRecipeIdsFrom`) so its advice references the user's actual in-app data rather than generic nutrition tips.
